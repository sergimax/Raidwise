## Что обнаружила повторная проверка

### P1. Закрытие вкладки может потерять ожидающие записи правки — F02, D01

В изолированном Chrome другая вкладка удерживала блокировку сохранения. После добавления рейда или списка BiS черновик появился в `sessionStorage`, а общее сохранение ещё отсутствовало. В обоих случаях вкладку закрыли до освобождения блокировки. При открытии приложения в новой вкладке правки и черновика не было. Перезагрузка той же вкладки покрыта штатным тестом и восстанавливает правки.

Нужно сохранять незаписанный черновик в хранилище, доступном новой вкладке, и сохранять проверку конфликтов. Если браузер не может сохранить черновик надёжно, нужен сигнал перед уходом со страницы и возможность скачать копию. [Очередь записи](../../../src/hooks/use-local-save.ts), [хранилище черновика](../../../src/storage/pending-save.ts).

### P2. Повреждение общего сохранения может заблокировать восстановление из файла — F01, F03–F04, D12

В `raidwise-workspace` версии 1 оставили корректный раздел трекера с персонажем, а значение раздела BiS заменили на `null`. Chrome показал предупреждение и кнопку выгрузки исходника, но персонаж исчез из таблицы. Корректная копия открылась в предпросмотре с недоступной кнопкой замены. Исходная строка осталась неизменной.

Нужно отдельно разбирать оба раздела известной версии и позволить заменить повреждённую запись из проверенной копии с явным подтверждением, сверкой исходной строки и атомарной записью. Для будущих версий защита от замены должна сохраняться. [Чтение общего сохранения](../../../src/storage/workspace-save.ts), [проверка доступности восстановления](../../../src/hooks/use-local-save.ts).

### P2. Повторное открытие не перезапрашивает сбойный JavaScript — D05, D07

Chrome заблокировал JavaScript раздела рейдов до появления экрана восстановления. После снятия блокировки **Open Raidwise again** оставила экран ошибки, число запросов осталось прежним. **Reload app** запросила файл заново и вернула таблицу. Штатный сценарий сбоя JSON-справочника проходит отдельно.

Нужно различать ошибку рендера и отказ загрузки модуля, показывать подходящее действие восстановления и закрепить сценарий в браузерном тесте. [Загрузка раздела рейдов](../../../src/components/app-route-content/index.tsx), [экран восстановления](../../../src/components/app-error-boundary/index.tsx).

## Исправления после повторной проверки

- F02, D01. Трекер и BiS записывают черновики под отдельными ключами в локальном хранилище. После закрытия вкладки ожидавшие записи правки доступны через **Открыть черновик** в соответствующей панели. Открытие требует явного действия, запись проверяет исходный снимок. Если долговременная запись черновика недоступна, приложение предупреждает перед уходом и предлагает скачать копию. Браузер может показать системное предупреждение после взаимодействия со страницей.
- F01, F03–F04, D12. Для повреждённой общей записи приложение показывает читаемые разделы и позволяет скачать исходную строку. После явного подтверждения проверенная копия заменяет оба раздела одной записью под блокировками. Сверяется исходная строка. Сохранения будущих версий остаются защищены от замены.
- D05, D07. При ошибке загрузки JavaScript экран восстановления предлагает перезагрузить страницу и запросить файлы заново. Для ошибки рендера доступно повторное открытие без перезагрузки. Браузерный тест блокирует JavaScript раздела рейдов и подтверждает восстановление после снятия блокировки.

Локально прошли линтер, production-сборка, 729 тестов Vitest и 16 проверок Chrome по счётчику Node test runner.
Покрытие строк — 87,53%, все пороги пройдены.
Браузерные тесты закрывают и открывают вкладки при ожидающей записи трекера и BiS, восстанавливают повреждённую общую запись из резервного файла и проверяют действие при отказе загрузки JavaScript.
