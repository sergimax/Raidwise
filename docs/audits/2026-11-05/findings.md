# Реестр находок

Контекст и результаты проверок: [обзор](README.md), [воспроизведение](verification.md). Ссылки ниже относятся к исходникам проверенного commit; номера строк зафиксированы для него.

## F01 — P1: корректный JSON с `null` внутри массива блокирует загрузку

**Подтверждение:** две исполняемые пробы, `TypeError`.

В [parse.ts](../../../src/storage/parse.ts) строки 73–75 приводят непроверенные массивы к типам сохранённых сущностей. `parseCharacters` (252+) и `toDungeonRecord` (81+) читают поля элементов без `isRecord`. [Миграции](../../../src/storage/migrate.ts) также предполагают корректные строки рейдов. `parsePayload` вызывается вне защитного `try` (parse.ts:339).

Воспроизведение в отдельном тестовом профиле: сохранить `{"schemaVersion":6,"characters":[null],"dungeons":[],"dungeonToggles":{}}` под ключом `raidwise` и открыть приложение. Legacy-вариант с `dungeons:[null]` ломается ещё в миграции. Хук загрузки бросает исключение; корневой Error Boundary отсутствует. Это сценарий повреждения/ручного изменения сохранения, не обычного ввода через форму.

**Исправление:** проверять каждый элемент как `unknown` до миграций и парсинга; возвращать структурированное предупреждение с частично восстановленными данными. Не заменять исходный JSON до решения пользователя. **Приёмка:** null/числа/массивы/объекты без полей в обоих массивах не обрушивают UI; валидные соседние строки сохраняются.

## F02 — P1: последние изменения теряются до истечения debounce

**Подтверждение:** проба изменения и unmount до таймера; сценарий reload/закрытия следует из жизненного цикла записи, отдельно в браузере с быстрым reload не прогонялся.

[use-tracker-domain.ts:37–47](../../../src/hooks/use-tracker-domain.ts) сохраняет состояние через 400 мс и отменяет таймер при cleanup. Нет flush по завершению жизненного цикла страницы. Пользователь может отметить CD и сразу обновить/закрыть страницу; изменение останется только в памяти. При unmount до 400 мс проба подтверждает отсутствие записи вообще.

В [use-bis-lists-domain.ts:43–56](../../../src/hooks/use-bis-lists-domain.ts) есть flush на React unmount, но это не обработчик ухода со страницы: наличие cleanup само по себе не решает browser reload. Штатный [browser persistence test](../../../scripts/browser/tracker-persistence.browser.mjs) специально ждёт записи и поэтому не ловит это окно.

**Исправление:** общая политика durable writes; выбрать немедленную запись небольшого состояния либо debounce с flush последнего committed state на подходящих событиях страницы и unmount. Не обещать сохранение при принудительном завершении процесса. **Приёмка:** изменение → reload до 400 мс; изменения BiS; быстрые последовательные операции; StrictMode и pending-save indicator при необходимости.

## F03 — P1: повреждённый tracker перезаписывается, предупреждение исчезает

**Подтверждение:** исполняемая проба с `{broken`.

[loadRaidTrackerState](../../../src/storage/parse.ts) возвращает пустое состояние и warning для невалидного JSON. [useTrackerDomain](../../../src/hooks/use-tracker-domain.ts) уже на первом mount планирует запись этого пустого состояния; спустя 400 мс успешная запись вызывает `setStorageError(null)`. Исходная строка исчезает, а предупреждение становится кратковременным. README описывает reset повреждённых данных, но отсутствие резервирования и исчезновение уведомления делают восстановление ненадёжным.

**Исправление:** разделить `loadWarning` и `saveError`, не автосохранять результат неудачной загрузки, предоставить выгрузку исходной строки и явный сброс. **Приёмка:** idle mount не изменяет повреждённый ключ; предупреждение остаётся до явного действия; после подтверждённого сброса запись снова работает.

## F04 — P2: несовместимая версия/повреждение BiS превращается в пустой store

**Подтверждение:** проба `schemaVersion:999`; ветки corrupt JSON и неизвестной tracker schema проверены чтением кода.

[storage/bis-lists/index.ts:129–152](../../../src/storage/bis-lists/index.ts) возвращает `EMPTY_STATE` и при неизвестной версии, и при исключении, без сигнала вызывающему коду. [useBisListsDomain](../../../src/hooks/use-bis-lists-domain.ts) сохраняет результат на mount. Проба подтверждает замену неизвестной схемы версией 1 с пустыми entries. Даже исправимый JSON не остаётся доступен для восстановления.

Для tracker [migrateStoredPayload](../../../src/storage/migrate.ts) явно понижает будущую версию до текущей; следующий save сериализует только известные поля. Это риск при rollback или одновременной работе старого/нового клиента, а не доказательство существования новой схемы сегодня.

**Исправление:** различать missing/corrupt/unsupported/ready для обоих stores; unsupported читать без записи или блокировать редактирование с понятным объяснением. **Приёмка:** незнакомая версия остаётся побайтно неизменной после mount/unmount, пользователь видит причину.

## F05 — P1: устаревшая вкладка может затереть изменения другой

**Подтверждение:** два независимых экземпляра hook на одном storage; полноценная двухвкладочная браузерная проба остаётся регрессионным тестом для исправления.

[Tracker domain](../../../src/hooks/use-tracker-domain.ts) и [BiS domain](../../../src/hooks/use-bis-lists-domain.ts) читают snapshot при mount и затем сохраняют весь документ. Нет подписки на `storage`, revision или обнаружения конфликта.

Сценарий: A и B открыты на одном исходном состоянии; A добавляет персонажа и сохраняет; B добавляет рейд из своего старого snapshot. Запись B удаляет персонажа A. Исполняемая проба подтверждает именно такую последовательность с двумя stores.

**Исправление:** согласование вкладок и проверка revision перед записью; определить поведение при dirty-state конфликте. Простое добавление `storage` listener не гарантирует отсутствие гонок. **Приёмка:** изменения A/B не пропадают молча; конфликт виден, есть восстановление/выбор версии; аналогичный тест для BiS.

## F06 — P2: первая ошибка загрузки JSON блокирует последующие попытки

**Подтверждение:** проба loader; цепочка провайдера проверена статически.

[lazy-json.ts:6–14](../../../src/data/lazy-json.ts) навсегда кэширует отклонённый Promise. [ensure-wow-data.ts](../../../src/data/ensure-wow-data.ts) дополнительно кэширует aggregate promises. [WowDataProvider:23,35](../../../src/contexts/wow-data-provider.tsx) подписывается только на успех, без ошибки/повторной попытки. При отказе chunk-запроса readiness не наступает; восстановление сети не запускает новый import. Проба вызывает loader дважды и получает один вызов import и два отклонения.

**Исправление:** явные состояния loading/ready/error, сброс кэша при отказе на всех уровнях, retry и обработка устаревших chunk URL после deploy. **Приёмка:** один отказ → повтор → успешная гидратация, без unhandled rejection; EN/RU и частично загруженные справочники.

## F07 — P2: редактирование удаляет сохранённую идентичность шаблонного рейда

**Подтверждение:** проба update + resolve.

[use-tracker-domain.ts:98–115](../../../src/hooks/use-tracker-domain.ts) собирает `DungeonRecord` заново и не переносит `raidKey`. Пока имя стандартное, [resolveDungeonRaidKey](../../../src/utils/resolve-dungeon-raid-key.ts) восстанавливает связь по имени. После переименования, например в «Friday team», ключ уже не определяется. Это влияет на точные loot sources, иконки, поиск и связанные hints.

**Исправление:** определить явный контракт — изменение отображаемого имени или замена типа рейда. В первом случае сохранять `raidKey`, во втором дать явный выбор/сброс связи и пересогласовать itemLevel/size/difficulty. Слепое сохранение старого ключа при замене ICC на другой рейд тоже неверно. **Приёмка:** тесты обоих сценариев и подсказок после reload.

## F08 — P2: ошибка копирования legacy-key скрывает доступные legacy-данные

**Подтверждение:** проба с `QuotaExceededError`.

[local-storage-migrate.ts:10–22](../../../src/utils/local-storage-migrate.ts) объединяет read, copy и remove в один `try`. При успешном чтении legacy и неудачном `setItem` возвращает `null` вместо уже прочитанной строки. Caller видит отсутствие данных. Legacy-ключ остаётся на месте, то есть это прежде всего потеря видимости данных, а не доказанная физическая потеря исходника.

**Исправление:** возвращать прочитанные legacy-данные независимо от успеха переноса, сообщать о невозможности миграции и удалять legacy только после успешной записи. **Приёмка:** отказ copy/remove не обнуляет состояние в памяти; повторная миграция безопасна.

## F09 — P2: tooltip помечается загруженным до успеха запроса

**Подтверждение:** статический анализ [wow-item-tooltips-loader/index.tsx:10–20,33–54](../../../src/components/wow-item-tooltips-loader/index.tsx).

`loadedLocales.add(locale)` вызывается до загрузки script; обработчиков load/error нет. После временного отказа CDN/блокировки запроса повторное взаимодействие ничего не делает. Наличие элемента script дополнительно препятствует новой попытке. Комментарий о первом успешном load расходится с реализацией.

**Исправление:** track loading/loaded/error, load/error handlers, контролируемый retry с удалением неуспешного script. **Приёмка:** error → retry → load для обеих локалей; один запрос при параллельных взаимодействиях.

## F10 — P2: неизвестные URL внутри `/raids/` обходят страницу 404

**Подтверждение:** статическая трассировка маршрута.

[app-route-content/index.tsx:48](../../../src/components/app-route-content/index.tsx) принимает `raids/*`. [useAppRoute](../../../src/routing/app-route.ts) для `/raids/typo` возвращает `/not-found`, но [useOverlayPanels](../../../src/hooks/use-overlay-panels.ts) лишь получает отсутствие активной панели; [TrackerLayout](../../../src/components/tracker-layout/index.tsx) продолжает показывать tracker. Верхний catch-all сюда не попадает.

**Исправление:** перечислить дочерние маршруты или обрабатывать неизвестный путь внутри raid workspace. **Приёмка:** `/raidwise/raids/typo` показывает локализованную 404; известные пути, trailing slash и history сохраняют поведение.

## F11 — P3: кнопки увеличения и уменьшения имеют одинаковое accessible name

**Подтверждение:** [gear-pick-rules.tsx:50,63](../../../src/components/gear-pick-panel/gear-pick-rules.tsx), обе используют `maxSoftsAria`.

В обеих локалях имя описывает параметр, а не действие. По именам двух icon-only кнопок пользователь screen reader не может различить «увеличить» и «уменьшить». Axe на странице Settings эту семантическую проблему не выявляет.

**Исправление:** отдельные EN/RU action labels с текущим значением при необходимости. **Приёмка:** различимые `getByRole("button", {name: ...})` и проверка клавиатурной навигации.

## F12 — P3: отказ clipboard не получает обратной связи

**Подтверждение:** `catch { return false/return; }` в [gear-pick-copy-block](../../../src/components/gear-pick-panel/gear-pick-copy-block.tsx), [result-lines](../../../src/components/character-pick-panel/result-lines.tsx) и [bis-lists-panel](../../../src/components/bis-lists-panel/index.tsx).

Если браузер отклоняет Clipboard API, нажатие визуально ничего не делает. Текст доступен в интерфейсе, но причина отказа пользователю не объясняется.

**Исправление:** общий clipboard helper/hook с локализованным error status и способом ручного копирования. **Приёмка:** mocked rejection/отсутствие API показывают понятную ошибку, успешное копирование сохраняет индикацию.
